# Visual Hierarchy

Explains how users should scan pages and where emphasis belongs.

## Typography hierarchy

1. **Page eyebrow / section labels**
   - Small uppercase text.
   - Used to orient the user (“Work Queue”, “Review Work”, etc.).
2. **Page title**
   - Large, semibold, high contrast.
   - The primary answer to the screen’s question.
3. **Section headings**
   - Medium-small semibold.
   - Introduces a cluster of information.
4. **Body text**
   - Calm size with comfortable line-height for reading.
5. **Secondary metadata**
   - Small text for context (e.g., created time).

## Color hierarchy

Color is used for meaning and governance, not decoration:
- **Neutral / card surfaces**: background + border + soft shadow.
- **Badges**
  - Priority and Status convey governance state.
  - Critical/warning hues reserved for true governance moments.
- **Primary CTA**
  - Dominant and confident.
  - Secondary actions remain neutral.

## CTA hierarchy

- Each screen has one dominant next step.
- Primary CTA must be visually dominant:
  - stronger contrast
  - premium padding
  - clear placement in the card where the decision happens
- Secondary actions:
  - lower visual weight
  - neutral styling
  - avoid competing with primary CTA

## Information hierarchy

In any “review” card:
- Start with the “what” (client + matter type).
- Then “who” (assigned Digital Employee).
- Then governance context (PriorityBadge + StatusBadge).
- Then “when” (created time).
- Finally the “next step” (Review Work / Approve / etc.).

## How users should scan every page

Use a predictable reading pattern:
1. Eye to title + eyebrow.
2. Move to the main decision area.
3. Confirm governance badges.
4. Review required content blocks.
5. Act via the primary CTA.
