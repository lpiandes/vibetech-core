# Standard Operating Procedure (SOP)

## Purpose

Define the *business workflow* for the Client Update Employee in Legal OS.

This SOP is not executable code. It describes how a human-reviewed employee should behave and what must be approved.

## Inputs (Business)

- Case activity / timeline changes
- Whether a meaningful event occurred
- Time since last client update
- Attorney review/approval status (when applicable)

## Business Workflow

### Step 1: Determine if something meaningful happened

- If yes: prepare a client-friendly status update *without legal advice*.
- If no: proceed to cadence checking.

### Step 2: Check update cadence

- If the client has gone too long without an update: prepare a client update draft.
- If cadence is acceptable: prefer waiting.

### Step 3: Draft an update (internal draft)

- Draft a professional message that:
  - stays factual and clear
  - avoids promises and outcomes
  - does not discuss settlement values
  - does not contradict an attorney

### Step 4: Enforce human approval gate

Always require attorney approval before any client communication.

- If attorney approval is present: proceed to the “approved send” step later.
- If attorney approval is not present:
  - request attorney approval
  - remind the attorney if review is needed soon
  - wait without sending anything to the client

### Step 5: Decide whether to wait

If key facts are missing for a safe update, queue no action and document what information is needed.

## Guardrails (Always Enforced)

- Never provide legal advice.
- Never promise outcomes.
- Never discuss settlement values.
- Never contradict an attorney.
- Always remain professional.
- Always require attorney approval before client communication.
