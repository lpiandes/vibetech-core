# Visual Hierarchy

Visual hierarchy defines where user attention naturally flows.
It is designed for executives who need answer-ready scanning.

## Display hierarchy (largest, least frequent)
- `Display` is for top-level executive framing only (e.g., page headline).
- Purpose: “What is this screen and why should I care?”

## Page hierarchy
- Page title (or experience headline)
- Executive summary section
- Supporting sections in deterministic order:
  1. KPI cards
  2. Trends
  3. Insights
  4. Recommendations
  5. Metrics/evidence (optional depth)

## Section hierarchy (what is a section)
- Each section:
  - has a title,
  - contains a small number of scannable items,
  - uses whitespace and consistent padding,
  - has an “attention outcome” (recorded/missing, direction, importance).

## Card hierarchy
- Cards are the atomic attention units.
- Card headline: short, business-labeled.
- Card body: meaning + evidence (never walls of text).

## KPI hierarchy
- KPI card priority is derived from deterministic importance/priority tier.
- KPI status drives attention:
  - recorded vs missing
  - consistent badge semantics across all OS modules

## Alert hierarchy
- “Alerts” are executive attention signals, not just visual decoration.
- Insights represent attention that requires review.
- The hierarchy must avoid ambiguity: if something requires attention, it is explained and evidenced.

## Recommendation hierarchy
- Recommendations are ordered and labeled as “actions.”
- Every recommendation must include:
  - actionType label
  - priority tier
  - evidence items (what recorded fact triggered the suggestion)

## Timeline hierarchy (where applicable in future)
- Timeline updates should follow:
  - latest-first
  - direction semantics
  - evidence with minimal text

## Attention flow (natural reading order)
1. Executive summary (“how are we doing?”)
2. KPI cards (what are the key measured values?)
3. Trends (are we improving, stable, declining, or unknown?)
4. Insights (what requires attention?)
5. Recommendations (what should we do next?)
6. Metrics/evidence (why those decisions are suggested)
