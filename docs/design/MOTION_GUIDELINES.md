# Motion Guidelines (Executive Systems)

## Motion philosophy
Motion is a system language:
- It communicates state transitions.
- It confirms intent and outcomes.
- It never distracts from decision making.

## What motion should communicate
- Page transitions (context switching with continuity)
- Card expansion (revealing evidence)
- Loading (progress indication without anxiety)
- Success/failure (deterministic feedback)
- Health changes (subtle attention shift)
- Timeline updates (directional changes)
- Notifications (action-needed vs informational)

## What motion should never do
- Never animate continuously without meaning.
- Never “wiggle” attention away from actual attention signals.
- Never create ambiguous causality (“did something happen or not?”).

## Principles
1. Motion should explain.
2. Motion should never distract.
3. Motion always has purpose.
4. Motion must remain deterministic with respect to inputs (same data -> same motion outcomes).

## Examples mapped to common executive interactions
- **Loading:** shimmer placeholders and stable layout skeletons.
- **Success:** deterministic confirmation microcopy and subtle visual acknowledgment.
- **Failure:** clear error surfaces with stable positioning and actionable next steps.
- **Attention shift:** use subtle transitions so attention moves only when needed.

## Accessibility considerations (foundation-level)
- Keep motion subtle and optional (avoid forcing continuous animation).
- Ensure semantic information remains available without motion.
